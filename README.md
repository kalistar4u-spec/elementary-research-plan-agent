# 범용 연구계획서 에이전트 — 강의교안 반영본

초등 교사의 수업문제를 실행 가능한 연구 설계안으로 바꾸는 프로젝트형 지침이다. 스킬 설치 파일이나 독립 실행 프로그램이 아니다.

## 시작 방법
1. 이 폴더 전체를 별도 프로젝트 폴더로 가져온다. 최상위 파일명이 정확히 AGENTS.md인지 확인한다.
2. Codex에서 그 폴더를 작업공간으로 열고 아래 예시처럼 수업문제를 입력한다.
3. 연구문제·자료·분석 연결을 확인하고, 검수 점수표를 받은 뒤 승인하거나 수정 의견을 준다.
4. 문헌 보완을 원하면 설계안 승인 후 별도 문헌검색 단계를 요청한다.

예시: “5학년 영어 한 학급에서 발표 후 수정이 잘 일어나지 않습니다. 6차시 안에 가능한 연구 설계안을 만들어 주세요. 실제로 관찰할 학생 변화부터 함께 정해 주세요.”

비AI 예시: “4학년 음악에서 모둠 합주 때 일부 학생만 의견을 냅니다. 역할 순환과 성찰 기록을 활용한 실행연구를 설계해 주세요. AI와 문헌검색은 아직 쓰지 않겠습니다.”

## Plan · Goal · Loop 구분
- Plan: 모호한 요구를 질문으로 좁히고 실행 순서와 완료 조건을 정한다.
- Goal: 사용자가 명시적으로 요청한 최종 결과를 추적한다. 실제 기능 사용 여부와 프롬프트의 용어를 혼동하지 않는다.
- Loop: 산출물을 채점하고 미달 부분을 고친다. 최초 채점 + 최대 2회 수정·재채점이다.
- Gate: 점수 통과와 교사 승인을 확인한 뒤 다음 담당 단계로 인계한다.

강의 실습은 Plan 기능으로 에이전트 개선 계획을 세우고, 다음 요청에서 Goal 기능으로 승인된 계획을 구현하는 방식이다. 파일에 이 단어들이 있다는 것만으로 실습을 수행한 증거가 되지 않는다. 해당 기능이 제공되지 않는 환경에서는 일반 계획·체크리스트로 대체하며 실제 기능 사용을 주장하지 않는다.

## 파일 구성
- AGENTS.md: 연구 설계 담당의 기본 지침과 검수·승인 규칙.
- agents/literature.md: 필요할 때 읽는 별도 문헌검색 담당 지침. 자동으로 독립 에이전트를 생성하지 않는다.
- tests/시나리오.md: 동일 입력으로 개선 전후를 비교하는 테스트 기준.
- CHANGELOG.md: 변경 내용과 검증 범위.
- projects/<핵심주제>/: 실행 후 연구계획서·문헌근거표·인계서·검수기록·진행상태가 저장되는 위치.

기본 설계안 작성에 별도 파싱 스킬은 필요 없다. 문헌검색에는 실제 검색 접근 수단이 필요하다. 선택 스킬 kordoc-document-parser와 source-grounded-audit은 별도 설치 사항이며 이 폴더에 포함하지 않는다. 외부 LLM 비용·전송 범위는 실행 전에 설명하고 승인을 받는다.

## 강의 반영
- 38·41쪽: 프로젝트형 AGENTS.md, 설계와 문헌검색의 역할 분리.
- 44~47쪽: 자가 검수 후 교사 평가, 점수와 횟수 상한을 함께 적용.
- 48쪽: 루트 지침 200줄 이하를 이 과제의 관리 목표로 사용한다. 보편적인 성능 보장 기준으로 해석하지 않는다.
- 50~56쪽: 문헌검색 인계 내용과 통과 게이트.
- 69·74~77·81쪽: 사용법, 공개 제외 대상, 테스트와 변경 이력.

## 공유와 제한
GitHub에 지침을 올리는 것과 웹에서 에이전트를 실행하는 것은 다르다. 공개 대상은 이 폴더의 지침·사용법·개인정보 없는 테스트 파일이다.
학생자료·API 키·.env·공개 권한 없는 논문 원문·실제 연구 산출물은 기본적으로 공개하지 않는다.
이 버전은 지침의 구조와 판정 규칙을 확인한 상태다. 실제 교사 대화 전체, 실시간 문헌검색, 독립 멀티에이전트 실행을 완료한 것으로 간주하지 않는다.
교사 승인과 학교·기관이 요구하는 연구 수행 승인은 별개다.
